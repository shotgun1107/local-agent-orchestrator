# 연구 운영 결정 기록

## 2026-09-16 — 연구 관리와 실행 공간 분리

- 사용자 의도: 상용 서비스 개발보다 연구 기획·실험·검증의 연속성에 집중한다.
- Documents의 기존 문서 폴더는 총괄·운영의 기준 공간으로 유지한다. 이동 안내만 남기는 이전 구조를 대체한다.
- LAO는 코드 작성, 실행, 검토, 실험 및 환경을 모으는 공간이다.
- 순환: 연구 질문·계획 → LAO 작업 → 근거·결과 보고 → 문서 폴더에서 해석·다음 방향 결정.

## 2026-09-16 — 하나의 Git 저장소로 공동 이력 관리

- 기존 `local-agent-orchestrator`, `origin/codex/phase-d-artifacts`를 유지한다.
- 관리 문서의 실제 편집 공간과 Git 전달본을 구분한다. 관리 폴더 자체는 Git 저장소가 아니다.
- 고정 허용 목록과 이전 일치 해시로 `collect`/`refresh`한다. 양쪽 수정, 삭제, 경로 변경은 자동 해결하지 않는다.
- 별도 원격 저장소·공유 링크·중복 clone·Git 이력 재작성은 만들지 않는다.
- 새 PC는 코드를 수신하고 환경은 명세로 재구성한다. 설치된 venv·인증·Docker image를 Git에 넣지 않는다.
- 과거 원본 보존과 새로운 실행 준비는 별개다. 역사적 state·seal·절대경로를 새 환경에 맞춰 고치지 않는다.

이 결정은 운영 구조에 대한 것이다. 후속 연구 가설, 실험 대상, 새 experiment나 모델 사용 승인을 포함하지 않는다.

## 2026-09-16 — 감사의 F8·F9·F3부터 교정

- 감사 설명 후 사용자가 제안 순서의 진행을 승인했다. 실제 실행 설정·필수 입력·완료 증거의 연결을 먼저 고친다.
- 사용자 일시 정지 요청을 따랐고 재개 지시 뒤 나머지 경계·회귀 검증을 수행했다.
- 과거 PASSED에 새 증거를 소급 추가하거나 자동 재실행하지 않는다. 증거가 없거나 달라진 복구는 BLOCKED로 둔다.
- 이번 승인은 세 코드 경계와 model-free 검증·기록에 한정한다. F5 등 잔여 감사와 새 연구/실험은 분리한다.
