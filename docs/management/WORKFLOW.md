# 역할과 작업 진행 방식

## 일상 작업

| 단계 | 수행 공간 | 남기는 자료 |
|---|---|---|
| 연구 기획 | 관리 문서 폴더 | 질문·가설·범위·판정 기준·중단 조건 |
| 구현·검토·model-free 검증 | LAO/repo | 코드·시험·설정·공유 가능한 기술 결과 |
| 승인된 실험 | LAO/run, evidence | 원본 state/raw/seal, 환경·실행 증거 |
| 결과 인수 | 관리 문서 폴더 | 확인된 사실·한계·해석·결정·다음 작업 |
| PC 전환 | 기존 Git 저장소와 별도 자료 전달 | 작업 commit·인수인계·환경 상태·미전달 항목 |

관리자가 정하지 않은 실험을 실행자가 임의로 이어가지 않는다.
모델 없는 코드·문서 작업과 Live 실행 승인을 구분하며, 상세 안전 관문은 저장소 AGENTS.md를 따른다.

## 관리 문서 반영

회사 예시(다른 PC는 자기 경로로 대체):

```powershell
C:\LAO\env\v23\Scripts\python.exe -B C:\LAO\repo\tools\workspace\management_sync.py status --management-root 'C:\Users\SSAFY\Documents\간단한 ai 오케스트라 구축하기'
```

- `equal`: 일치. 관리 폴더에서 편집해도 된다.
- `management-ahead`: 관리 폴더에 미반영 편집이 있다. 내용을 검토하고 `collect`한다.
- `repository-ahead`: Git 쪽이 바뀌었다. `refresh`한다.
- `initialize`: 아직 관리 사본이 없다. `refresh`로 처음 복원한다.
- `conflict` 또는 `missing-file`: 자동 반영 중단. 삭제를 전파하지 않으며 양쪽 내용을 보존해 해결한다.

`status`는 읽기 전용, `collect`/`refresh`는 목록에 있는 6개 파일만 바꾼다.
Git stage·commit·push는 이 도구가 하지 않는다. 다른 세션이나 편집기가 같은 파일을 수정 중일 때 반영하지 않는다.
`.lao-management.json`은 이 PC의 연결·기준 해시다. Git에 넣거나 다른 PC로 복사·수동 수정하지 않는다.

## 회사에서 집으로, 집에서 회사로

떠나기 전: 관리 문서 갱신 → `status`/`collect` → `sync` 받기 완료 →
정확한 변경만 검사·커밋·일반 push → 기존 인수인계 자동 블록 갱신·전송 → 남은 로컬 자료 보고.

도착 후: 양쪽 로컬 변경 확인 → `sync`로 원격 고정·수신 → 인수인계 확인 →
`refresh` → 개발 환경 점검 → 마지막 승인된 작업 재개.
도착한 PC에도 미반영 문서가 있으면 먼저 그 작업을 보존·검토한다. 무조건 새 원격본으로 덮어쓰지 않는다.

완료 보고는 Git, 관리 문서 반영, 개발 환경, Live 환경, 별도 원본 전달을 구분한다.
다른 PC에서 읽히지 않는 로컬 경로만 기록하고 인수인계가 끝났다고 하지 않는다.

## 결과 보고 최소 항목

- 작업 목적과 승인 범위, 작업 commit
- 검증 방법·실제 결과·실패/환경 문제·해석의 한계
- 공유한 자료의 저장소 경로 및 별도 원본 위치·무결성 근거
- 완료/진행 중/미확인, 다음 작업과 필요한 사용자 결정

고정 원본 보고서는 기술 문서에 보존하고, 이 폴더의 상태·다음 작업·결정만 최신으로 유지한다.
