## 6. 집 Git 동기화

집의 기존 clone에서 먼저 보존 상태를 확인한다.

```powershell
Get-Location
git remote get-url origin
git branch --show-current
git rev-parse HEAD
git status --short --untracked-files=all
git status -sb
git stash list
```

origin이 다르거나 detached HEAD, modified/staged/untracked 파일, stash가 있으면
`reset`, `clean`, `checkout`, `stash`, `rebase`, `pull`로 숨기거나 버리지 말고 멈춘다.

깨끗할 때만 다음을 실행한다.

```powershell
git fetch origin
git log --oneline --branches --not --remotes
git merge-base --is-ancestor `
  e295b1083b0464796f93c6a66739bfbbf25ee090 `
  origin/codex/phase-d-artifacts
git switch codex/phase-d-artifacts
git pull --ff-only origin codex/phase-d-artifacts
```

회사에만 또는 집에만 있는 commit이 보이면 임의 병합하지 않는다. 동기화 후 확인한다.

```powershell
git rev-parse HEAD
git rev-parse origin/codex/phase-d-artifacts
git rev-parse 'HEAD^{tree}'
git rev-parse 'origin/codex/phase-d-artifacts^{tree}'
git status --porcelain=v1
git diff --exit-code origin/codex/phase-d-artifacts -- .
```

HEAD, tree가 각각 같고 status가 비어 있으며 diff가 0이어야 한다. 새 clone이 정말
필요한 경우에만 다음을 사용한다.

```powershell
git clone --branch codex/phase-d-artifacts `
  https://github.com/shotgun1107/local-agent-orchestrator.git
```

## 8. Git·Docker·VM·DB 복원

### Git

회사 repository local 설정은 종료 시 `core.autocrlf=true`, `core.longpaths` 미설정이었다.
실행 코드는 이 전역값을 신뢰하지 않고 첫 Git 명령부터 자체 통제한다. 집 checkout의
예측 가능성을 높이려면 clean pull 뒤 repository-local로 다음을 권장한다.

```powershell
git config --local core.longpaths true
git config --local core.autocrlf false
git status --short --untracked-files=all
```

설정 뒤 tracked diff가 생기면 파일을 되돌리지 말고 보고한다.

### Docker

- Docker Desktop의 Linux container backend가 필요하다.
- repository에는 Compose 파일이 없다.
- Judge image 정의는
  `tools/benchmark-runner/docker/profile-r-judge/Dockerfile`과
  `requirements.lock`이다.
- Dockerfile은 Python base image digest를 고정하지만 `apt-get` 저장소 시점이 바뀔 수
  있어 재빌드 결과가 회사 image digest와 같다고 보장하지 않는다.

source로 재빌드하는 명령은 다음과 같다.

```powershell
docker build `
  --file .\tools\benchmark-runner\docker\profile-r-judge\Dockerfile `
  --tag local-agent-orchestrator/profile-r-judge:company-r07-noprov `
  .\tools\benchmark-runner\docker\profile-r-judge
```

digest가 `ba83a183...330ab`와 다르면 기존 qualification v10의 exact Docker identity로
취급하지 않는다. 그 경우 새 qualification 없이 Live로 진행하지 않는다.

### VM

repository가 관리하는 Vagrant/별도 VM 설정은 찾지 못했다. Docker Desktop 내부 Linux
VM의 상세 설정은 repository 정본이 아니며 이번 종료 점검에서 미검증이다.

### DB와 state

- 외부 DB 서비스나 migration은 없다.
- B1 원장은 각 state root 안의 SQLite `ledger.sqlite`다.
- 기존 live experiment를 다른 PC에서 이어가려면 해당 state/artifact/raw root 전체를
